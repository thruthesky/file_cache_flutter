# 🔴🔴🔴 필수 파라미터: DTD URI 🔴🔴🔴

> **⛔ $ARGUMENTS 에서 DTD URI(`ws://127.0.0.1:xxxxx/yyyyyyy=/ws` 형식)가 반드시 포함되어야 합니다. ⛔**
> **DTD URI가 없으면 즉시 에러 메시지를 출력하고 디버깅을 종료합니다.**
>
> DTD URI가 없는 경우 다음 메시지를 출력하고 즉시 종료:
> ```
> ❌ 에러: DTD URI가 제공되지 않았습니다.
> 사용법: /debug <DTD_URI> <디버깅할 내용>
> 예시: /debug ws://127.0.0.1:12345/abcdef=/ws 로그인 화면에서 크래시 발생
> DTD URI는 Flutter 앱이 디버그 모드로 실행 중일 때 터미널에 표시됩니다.
> ```

# 🔴🔴🔴 디버그 실행 지침 — 절대 규칙 🔴🔴🔴

> **⛔⛔⛔ 실행 중인 앱을 절대로 중단하지 않는다. ⛔⛔⛔**
> **앱 종료/재실행, Flutter Driver, E2E 테스트, `flutter run`, `flutter drive`, `flutter test` 등은 절대 금지.**
> **오직 DTD Hot Reload만 사용하여 코드 변경을 반영한다.**

# 🔴🔴🔴 랄프 루프 (Lalph Loop) — 절대 준수 디버깅 방식 🔴🔴🔴

> **⛔⛔⛔ 이 디버깅 커맨드의 핵심은 랄프 루프이다. ⛔⛔⛔**
> **사용자에게 "확인해주세요", "어떻게 할까요?" 등을 묻지 않는다.**
> **스스로 판단하고, 스스로 수정하고, 스스로 검증하며, 문제가 해결될 때까지 절대 멈추지 않는다.**

## 랄프 루프 핵심 원칙

1. **자율 반복**: 사용자 입력을 기다리지 않고 스스로 코드 수정 → 검증 → 재수정을 반복한다.
2. **시각적 검증**: 매 반복마다 반드시 스크린샷을 캡처하여 눈으로 결과를 확인한다.
3. **데이터 검증**: 화면이 이상하면 curl로 API 데이터를 직접 확인하여 원인을 파악한다.
4. **무한 반복**: 문제가 해결될 때까지 루프를 절대 중단하지 않는다. 3회, 5회가 아니라 해결될 때까지 계속한다.
5. **자동 정리**: 문제 해결 후 임시 코드를 자동으로 제거하고 최종 Hot Reload까지 완료한다.

## 랄프 루프 실행 단계

```
┌─→ 1. initState()에 해당 페이지로 이동하는 임시 코드 작성
│   2. DTD Hot Reload 실행
│   3. 스크린샷 캡처 → Read 도구로 화면 확인
│   4. 문제가 해결되었는가?
│      ├─ NO → 5단계로
│      └─ YES → 7단계로
│   5. 원인 분석:
│      a. curl로 API 데이터 확인
│      b. 콘솔 로그 확인
│      c. 코드 수정
└── 6. → 2번으로 돌아가 반복 (해결될 때까지 무한 반복)
    7. 해결 완료 → initState()의 임시 코드 제거 → DTD Hot Reload → 완료
```

> **⛔ 중간에 멈추고 사용자에게 보고만 하는 것은 랄프 루프 위반이다. ⛔**
> **반드시 직접 수정 → 확인 → 재수정을 반복하여 문제를 끝까지 해결한다.**

### 스크린샷 확인

코드 변경 후 Hot Reload를 실행한 뒤, 시뮬레이터 스크린샷을 캡처하여 앱이 올바로 동작하는지, 데이터가 올바로 표시되는지 시각적으로 확인한다.

```bash
sleep 1 && xcrun simctl io booted screenshot /Users/thruthesky/tmp/debug_screenshot.png 2>&1 && echo "스크린샷 완료"
```

- `sleep`은 Hot Reload 후 UI 렌더링 대기 시간 (1~3초 조정 가능)
- 스크린샷 파일명은 디버깅 대상에 맞게 변경 (예: `company_masonry_3.png`)
- 캡처한 스크린샷을 Read 도구로 확인하여 UI 레이아웃, 데이터 표시, 에러 상태를 검증

### API 데이터 확인

스크린샷에서 데이터가 올바르지 않거나 빈 화면이 표시될 때, curl로 필고 v7 API에 직접 접속하여 서버 응답 데이터를 확인한다.

```bash
curl -s -X POST 'http://192.168.0.26/api.php' -d 'method=company.list&status=a&limit=5' | python3 -c "
import json, sys
data = json.load(sys.stdin)
items = data.get('items', data.get('companies', []))
if not items:
    print('키 목록:', list(data.keys()))
    if 'items' not in data and 'companies' not in data:
        for k, v in list(data.items())[:5]:
            print(f'{k}: {repr(str(v)[:80])}')
else:
    for i, c in enumerate(items[:5]):
        name = c.get('name', '')[:30]
        title_img = c.get('title_image_url', '')
        photo = c.get('photo_url', '')
        logo = c.get('logo_url', '')
        print(f'[{i}] {name}')
        print(f'  title_image_url: {repr(title_img[:120]) if title_img else repr(title_img)}')
        print(f'  photo_url: {repr(photo[:120]) if photo else repr(photo)}')
        print(f'  logo_url: {repr(logo[:120]) if logo else repr(logo)}')
        print()
" 2>&1
```

- API method, 파라미터, 파싱 필드는 디버깅 대상에 맞게 변경
- 서버 응답의 키 구조, 데이터 값, URL 형식 등을 확인하여 앱 코드와 비교
- API 데이터가 올바른데 앱 표시가 잘못되면 → 프론트엔드(Dart) 코드 문제
- API 데이터 자체가 잘못되면 → 백엔드 또는 API 호출 파라미터 문제

### 랄프 루프 흐름도

```
┌─────────────────────────────────────────────────┐
│              코드 수정 (Dart 파일)                │
└──────────────────────┬──────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────┐
│           DTD Hot Reload 실행                    │
└──────────────────────┬──────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────┐
│    스크린샷 캡처 (xcrun simctl screenshot)        │
└──────────────────────┬──────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────┐
│          스크린샷으로 결과 확인                    │
├──────────────┬──────────────────────────────────┤
│  해결됨 ✅   │         해결 안 됨 ❌              │
│              │              ▼                    │
│              │  curl로 API 데이터 확인            │
│              │  콘솔 로그 분석                    │
│              │  원인 파악                         │
│              │              ▼                    │
│              │     코드 수정으로 돌아감 ↩️         │
└──────────────┴──────────────────────────────────┘
        ▼
  임시 코드 제거 → Hot Reload → 완료
```

| 규칙 | 설명 |
|------|------|
| **Hot Reload만 사용** | DTD URI를 통한 Hot Reload로만 코드 변경을 반영한다 |
| **앱 종료 금지** | 실행 중인 앱을 절대 종료하거나 재시작하지 않는다 |
| **E2E 테스트 금지** | Flutter Driver, integration_test, flutter_test 절대 사용 금지 |
| **flutter run 금지** | 앱을 새로 실행하는 어떤 명령도 사용하지 않는다 |
| **initState() 활용** | 페이지 이동, 테스트 데이터 주입 등은 initState()에 임시 코드로 작성 |
| **임시 코드 정리** | 디버깅 완료 후 initState()의 모든 임시 코드를 반드시 제거한다 |
| **스크린샷 필수** | 코드 변경 후 반드시 스크린샷으로 결과를 시각적으로 확인한다 |
| **랄프 루프 준수** | 문제가 해결될 때까지 수정→확인 루프를 자동으로 반복한다 |

플러터(Flutter) 앱을 디버깅하여 문제를 해결 해 주세요.

당신은 플러터 앱 개발을 위한 Dart 프로그래밍 언어 전문가 이며, Flutter 프레임워크와 관련된 다양한 라이브러리 및 도구를 활용하는 전문가 입니다.

이 문제를 해결하기 위해서 반드시, 다음의 과정을 따라 디버깅을 수행합니다.

1. 요청된 이슈와 관련된 현재 코드 베이스(필고 플러터 소스코드)를 Chain-of-Thought, Trees-of-Thoughts 방식으로 상세하고 정밀하게 파악하여, 주어진 이슈를 분석하고, 문제의 원인을 정확히 진단합니다. 참고: 아래의 '에러 분석 단계' 참조.

2. 문제 해결을 위한 계획을 수립하고, 기존 코드를 무시하고 처음부터 새롭게 접근합니다.

3. 문제 해결을 위해 기존의 코드를 확인하고, 필요하다면 기존의 코드를 삭제하고 완전한 새로운 방식으로 코드를 작성합니다. 참고: 아래의 '수행 단계' 참조.

4. **랄프 루프 실행**: DTD Hot Reload → 스크린샷 캡처 → 결과 확인 → (미해결시) curl API 확인 → 코드 수정 → 다시 Hot Reload. 이 루프를 사용자에게 묻지 않고 자율적으로 문제가 해결될 때까지 무한 반복합니다.


# 에러 분석 단계
- [ ] 먼저 현재 코드 베이스에서 에러가 발생하는 부분을 찾습니다. 에러가 발생하는 위치에의 부모 요소/DART파일/위젯과 형제 요소/DART파일/위젯 그리고 현재 요소/DART파일/위젯에 포함되는 하위 모든 DART 코드/함수/로직/DART파일 들을 모두 세밀하게 분석하여 연관 관계를 파악해서 코드의 구조와 데이터의 흐름, 전/후, 좌/우의 레이아웃과 코드 연결에 대해서 깊이 분석을 하세요.
- [ ] COT (Chain-of-Thought) 방식을 엄격히 준수합니다. 모든 작업에서 사고의 흐름을 명확히 설명합니다.
  - (1) 먼저 문제의 핵심을 다시 한번 더 상세히 파악하고,
  - (2) 문제 해결을 위한 계획을 수립한 다음,
  - (3) 기존의 코드를 완전히 무시하고, 처음 부터 새롭게 접근을 합니다.
  - (4) 문제 해결을 위해 완전히 새로운 코드를 작성하고,
  - (5) 단계별로 테스트를 진행합니다.
- [ ] TOT (Tree-of-Thought) 방식을 엄격히 준수합니다. 복잡한 작업을 작은 하위 작업으로 분해하여 처리합니다.
  - (1) 먼저 문제를 여러 개의 하위 문제로 분해(branch 화)합니다.
  - (2) 각 하위 문제에 대해 독립적인 해결책을 마련합니다.
  - (3) 각 하위 문제의 해결책을 통합하여 최종 해결책을 도출합니다.
- [ ] Dart 와 관련 된 문제라면, Flutter 위젯 단위로 코드를 분석하고, 각 위젯의 상태(state)와 속성(props), 이벤트(event) 등을 세밀하게 분석하여 데이터의 흐름과 위젯 간의 상호작용을 깊이 이해합니다.
- [ ] 콘솔 로그를 많이 출력하고 dev console 에 찍히는 메시지 확인

# 🔴 랄프 루프 금지 사항 🔴

| 금지 행위 | 올바른 행동 |
|-----------|------------|
| 1회 수정 후 사용자에게 "확인해주세요" | 스스로 스크린샷 찍어서 확인하고 계속 진행 |
| "이렇게 수정했습니다"로 끝내기 | 스크린샷으로 실제 동작 검증까지 완료 |
| 에러 원인을 추측만 하고 멈추기 | curl/로그로 데이터를 직접 확인하고 수정 |
| "다음에 확인해보세요" 등 떠넘기기 | 지금 당장 루프를 돌려서 해결 |
| 2~3회 시도 후 포기 | 해결될 때까지 무한 반복 (접근 방식을 바꿔가며) |
